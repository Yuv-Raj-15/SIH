📌 Executive Overview

PrivacyVision Agent is an airtight, privacy-first autonomous browser automation agent. Conventional AI browser agents upload raw screenshots and full DOM data to external cloud APIs, leaking sensitive passwords, banking credentials, UPI PINs, and personal emails. PrivacyVision solves this by running an on-device cryptographic vault, local NER / PII redaction, and reversible tokenization inside the browser. The cloud VLM (Vision-Language Model) only receives sanitized data and symbolic tokens, while real secrets are injected strictly on-device.

1. Definitions of All Key Concepts

Term Definition & Role in Project
PII (Personally Identifiable Information) Any sensitive personal data that belongs to a user: passwords, credit card numbers, CVVs, bank accounts, UPI PINs, phone numbers, and emails. The primary goal of PrivacyVision is ensuring 0 bytes of plaintext PII leave the device.
VLM (Vision-Language Model) A multimodal AI model capable of both visual understanding (analyzing screenshots) and natural language reasoning (deciding the next browser action like click or type).
AES-256-GCM Advanced Encryption Standard with Galois/Counter Mode. Military-grade symmetric authenticated encryption used to secure passwords and financial credentials in the local vault on your disk.
Local Encrypted Vault An on-device secure database managed by lib/vault.js using the Web Cryptography API (crypto.subtle). Decryption keys are derived on-device and never shared over the network.
NER (Named Entity Recognition) Pattern-matching and regex algorithms in lib/pii-scanner.js that scan DOM text to classify sensitive fields (e.g. recognizing that 4532... is a card, or pass... is a secret).
Reversible Tokenization Replacing real secrets in prompts and DOM text with symbolic placeholder tokens (e.g., [EMAIL_1], [PASSWORD]). The mapping table is kept in memory locally; cloud servers only see the token.
Visual Redaction Engine An offscreen canvas document that renders solid black masks and blur overlays directly over passwords, inputs, and detected face coordinates on full-tab screenshots before transmission.
Back/Forward Cache (bfcache) Chromium's in-memory cache for fast back/forward navigation. Our extension includes specialized state recovery to prevent port disconnection errors when pages navigate.
Ollama & LLaVA:7b A local AI runtime on localhost:11434 executing an open-source 7-billion parameter vision model, allowing 100% offline, cloud-free local inference.
GPT-5.6 Luna High-performance cloud reasoning model utilized in Hybrid mode. Receives only sanitized screenshots and tokenized instructions to plan complex web interactions.

2. Technology Stack & Component Architecture

🌐 Chrome Extension (Manifest V3)

  • Runtime: Modern JavaScript (ES2022+), Web APIs, HTML5, Vanilla CSS.
  • Local Vault (vault.js): AES-256-GCM encryption with PBKDF2 key derivation via crypto.subtle; stored in chrome.storage.local. Features cross-TLD brand matching (e.g. Amazon global).
  • DOM Analyzer (dom-analyzer.js): Extracts interactive elements (buttons, inputs, links), assigns stable numeric indices, and generates compact summaries for the AI.
  • PII Scanner (pii-scanner.js): Real-time regex and attribute scanner for emails, phones, UPI handles, cards, and passwords. Generates reversible token maps.
  • Action Injector (action-executor.js): Translates AI commands into native pointer/mouse/keyboard events. Automatically queries the vault and injects real passwords into target password inputs.

⚡ Server Backend (FastAPI / Python)

  • Runtime: Python 3.10+, FastAPI, Uvicorn asynchronous HTTP server.
  • VLM Client (vlm_client.py): Dual-backend driver supporting both 100% Local Ollama (llava:7b) and Cloud OpenAI-compatible endpoints (gpt-5.6-luna).
  • Action Parser (action_parser.py): Robust parser that normalizes raw model text, extracts JSON from codeblocks, and validates browser actions (click, type, scroll, navigate).
  • Prompt Engine (prompts.py): Comprehensive system prompts directing the AI to act step-by-step, inspect interactive elements, avoid action loops, and leverage on-device vault autofill.

3. Complete End-to-End Workflow

Phase 1: User Instruction & Task Launch
The user opens the extension popup, types a natural language goal (e.g., "buy samsung s25 ultra for me from amazon" or "login to Instagram"), and clicks ▶ Run Autonomous Agent. The background service worker (background.js) starts an iterative multi-step execution loop.
Phase 2: On-Device DOM Scan & PII Tokenization
The content script inspects the active webpage. The PIIScanner identifies sensitive text and inputs (emails, phones, account numbers, passwords). Real values are placed in an in-memory reversible token map (priya.sharma@gmail.com → [EMAIL_1]). The natural language prompt from the user is also sanitized so no raw PII leaves the browser.
Phase 3: Screenshot Capture & Offscreen Visual Redaction
chrome.tabs.captureVisibleTab takes a visual screenshot. Coordinates of password inputs and sensitive fields are passed to a Chromium offscreen document (offscreen.js). Solid black redaction rectangles and blurs are drawn over all sensitive regions. Only the masked image and tokenized DOM summary are sent to the reasoning engine.
Phase 4: Hybrid AI Reasoning (Local Ollama / GPT-5.6 Luna)
The Python server receives the sanitized screenshot, tokenized DOM summary, and sanitized instruction. Depending on VLM_BACKEND in .env:
  • Local Mode: Dispatches to local Ollama running llava:7b on http://localhost:11434 (100% offline, zero cloud data transfer).
  • Hybrid Mode: Dispatches to gpt-5.6-luna. Because all PII was already stripped on-device, the cloud planner receives zero confidential data.
The model outputs structured JSON with the next action (e.g., type query into search box, or click product).
Phase 5: On-Device Action Execution & Automatic Vault Injection
The background script forwards the actions to action-executor.js. Keystroke and pointer events are injected with framework compatibility.
Automatic Password Resolution: When the agent targets a password field, _resolveVaultValue queries Vault.findMatchingCredentials() for the current domain, retrieves the decrypted secret from the local AES-256 store, and enters it directly into the DOM.
Phase 6: Navigation Settlement & Multi-Step Continuation
If an action navigates the page (e.g. clicking an Amazon search result), the background worker detects the transition, gracefully handles the Chromium Back/Forward cache (bfcache) disconnect, waits for the new page to finish loading (tab.status === 'complete'), re-attaches content scripts, and continues to the next step until the goal is fully accomplished.
